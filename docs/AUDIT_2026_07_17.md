## 🔐 Segurança & RLS

### Scanners externos
Todos os scanners (agent_security, app_mcp, connector_security_scan,
supabase, supabase_lov, supply_chain) reportam **0 findings**.

### Supabase linter — 145 WARN (revistos, não bloqueadores)
- **1× `Extension in Public`** — extensões (provavelmente `pgcrypto`/`vector`)
  no schema `public`. Recomendação de longo prazo: mover para schema
  `extensions`. Não urgente, sem impacto de segurança operacional.
- **144× `SECURITY DEFINER function executable by anon/authenticated`
  (lint 0028/0029)** — falso positivo estrutural. As nossas RLS dependem
  de helpers `has_role`, `has_workspace_access`, `has_active_workspace_access`,
  RPCs de staff (`staff_delete_user`, `staff_transfer_workspace_program`,
  etc.) e funções de intake público. Todas **precisam** de `SECURITY DEFINER`
  para evitar recursão RLS e permitir operações mediadas — está documentado
  em `mem://user-roles`, `mem://security/*`. Cada função valida
  `auth.uid()` + role internamente, portanto o warning é esperado.
- **Ação:** manter. Rever se alguma função nova aparecer nesta lista
  sem justificação.

### Áreas já hardened (verificado)
- `user_roles` isolado com `has_role` SECURITY DEFINER ✅
- `profiles_safe` view (security_invoker) para PII ✅
- Rate-limits + tokens SHA-256 em booking público ✅
- 8h session timeout global ✅
- Storage RLS (contract uploads via service_role em edge functions) ✅
